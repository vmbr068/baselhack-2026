# Guide & Tutorial: Connecting Any AI Agent to Generated MCPs

This step-by-step guide explains how to connect your AI agents (**Claude Desktop**, **Cursor**, **Codex / OpenAI** scripts, **Luna** agents, etc.) to the dynamic MCP server generated by **MCP Creator**.

---

## 1. Architecture Overview

When a hotel website (e.g. `Grand Hotel Basel`) is scanned and generated by MCP Creator, a virtual MCP server is created with its tools (`check_availability`, `reserve_room`, `get_current_status`).

To allow agents to connect using standard **Model Context Protocol (MCP)** specifications, three access modes are provided:

```
                  ┌──────────────────────────────────────────────┐
                  │          Generated Hotel MCP Server          │
                  │ (check_availability, reserve_room, status)   │
                  └──────────────────────┬───────────────────────┘
                                         │
        ┌────────────────────────────────┼────────────────────────────────┐
        ▼                                ▼                                ▼
  [SSE Transport]                 [Stdio Bridge]                   [Direct REST API]
  Cursor / Web Agents             Claude Desktop / Local CLI       Codex / Luna / Scripts
  /api/v1/servers/:id/mcp/sse     bin/mcp-runner.mjs :id           /api/v1/servers/:id/call
```

| Transport Mode | Target Agents | Endpoint / Command |
| :--- | :--- | :--- |
| **SSE (Server-Sent Events)** *(Official MCP HTTP)* | Cursor, Web Agents, official MCP SDKs | `GET http://localhost:3000/api/v1/servers/latest/mcp/sse`<br>`POST http://localhost:3000/api/v1/servers/latest/mcp/messages` |
| **Stdio Bridge** *(Official MCP CLI)* | Claude Desktop, Antigravity, local CLI agents | `node <repo>/code/backend/bin/mcp-runner.mjs latest` |
| **REST / JSON API** *(Direct Fallback)* | Codex, Custom Python / LangChain / AutoGen | `POST http://localhost:3000/api/v1/servers/latest/call` |

> 💡 **Tip**: Replace `latest` with any specific server ID (e.g. `mcp_grand_hotel_basel_luxury_comfort_1793435670219`).

## 2. Connecting with Claude Desktop (stdio)

Claude Desktop natively supports the MCP protocol via **stdio** transport by executing a local script.

### Step 1: Open the Claude Desktop configuration file
- **On macOS**:
  ```bash
  code ~/Library/Application\ Support/Claude/claude_desktop_config.json
  ```
- **On Windows**:
  ```text
  %APPDATA%\Claude\claude_desktop_config.json
  ```

### Step 2: Add the generated MCP server
Add the following configuration inside the `"mcpServers"` object:

```json
{
  "mcpServers": {
    "hotel-basel": {
      "command": "node",
      "args": [
        "/Users/sacharamstein/Hackathon/baselhack-2026/code/backend/bin/mcp-runner.mjs",
        "latest"
      ],
      "env": {
        "MCP_BACKEND_URL": "http://localhost:3000"
      }
    }
  }
}
```

### Step 3: Test in Claude Desktop
1. Restart Claude Desktop.
2. The hammer icon 🔨 will appear in the bottom right corner with 3 tools:
   - `check_availability`
   - `reserve_room`
   - `get_current_status`
3. Ask Claude:
   > *"Find available rooms at Grand Hotel Basel from November 5 to November 8 for 2 guests."*
4. Claude automatically invokes the tool, Playwright scans the live website in the background, and Claude displays the available suites.

## 3. Connecting with Cursor / Windsurf / VS Code (SSE)

For Cursor or any IDE supporting MCP Server-Sent Events (SSE):

1. Open **Cursor Settings** (`Cmd + ,` or `Ctrl + ,`) > **Features** > **MCP Servers**.
2. Click **Add New MCP Server**:
   - **Name**: `Hotel-Basel`
   - **Type**: `sse`
   - **URL**: `http://localhost:3000/api/v1/servers/latest/mcp/sse`
3. Save. Cursor performs the SSE handshake, discovers the tools, and enables them in the Composer agent (`Cmd + I` or `Ctrl + I`).

## 4. Connecting with Codex / OpenAI / Python

If your agent runs on OpenAI / Codex models or custom Python scripts:

### Option A: Using the official Python MCP SDK (`mcp`)
```bash
pip install mcp
```
```python
import asyncio
from mcp import ClientSession
from mcp.client.sse import sse_client

async def run_agent():
    sse_endpoint = "http://localhost:3000/api/v1/servers/latest/mcp/sse"
    
    async with sse_client(sse_endpoint) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()
            
            # 1. Discover available tools
            tools = await session.list_tools()
            print("Discovered MCP tools:", [t.name for t in tools.tools])
            
            # 2. Search for available rooms
            result = await session.call_tool("check_availability", {
                "check_in": "2026-11-05",
                "check_out": "2026-11-08",
                "guests": 2
            })
            print("\nSearch results:\n", result.content[0].text)

asyncio.run(run_agent())
```

### Option B: Using OpenAI Function Calling directly (without MCP SDK)
You can directly convert our backend's schema (`/api/v1/servers/latest`) to OpenAI's tool format:

```python
import requests
import json
from openai import OpenAI

client = OpenAI()

# 1. Fetch generated MCP tools schema
server_config = requests.get("http://localhost:3000/api/v1/servers/latest").json()

openai_tools = [
    {
        "type": "function",
        "function": {
            "name": tool["name"],
            "description": tool["description"],
            "parameters": tool["parameters"]
        }
    }
    for tool in server_config["tools"]
]

# 2. Ask GPT-4o / Codex
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "What rooms are available for 2 guests from Nov 5 to Nov 8?"}],
    tools=openai_tools
)

# 3. Forward tool call to our backend executor
tool_call = response.choices[0].message.tool_calls[0]
call_result = requests.post(
    "http://localhost:3000/api/v1/servers/latest/call",
    json={
        "tool_name": tool_call.function.name,
        "arguments": json.loads(tool_call.function.arguments)
    }
).json()

print("Website execution response:\n", json.dumps(call_result, indent=2))
```

## 5. Connecting with Luna (and other Agent Frameworks)

For **Luna**:
1. **If Luna supports MCP SSE**: Configure the SSE URL:
   `http://localhost:3000/api/v1/servers/latest/mcp/sse`
2. **If Luna supports OpenAPI / Swagger import**: Luna can import the live OpenAPI spec from `http://localhost:3000/docs-json`.
3. **If Luna uses Custom Tool Actions / Webhooks**:
   - Endpoint: `POST http://localhost:3000/api/v1/servers/latest/call`
   - Request Body:
     ```json
     {
       "tool_name": "check_availability",
       "arguments": {
         "check_in": "2026-11-05",
         "check_out": "2026-11-08",
         "guests": 2
       }
     }
     ```

## 6. Safety & Human Confirmation (Human-in-the-Loop)

In accordance with [AGENTS.md](../AGENTS.md), irreversible actions (such as booking a room with personal details) require explicit human confirmation:

### End-to-End Booking Flow:
1. **Agent attempts reservation**:
   ```json
   {
     "room_title": "Deluxe Rhine View Suite",
     "guest_name": "Sacha Ramstein",
     "guest_email": "sacha@baselhack.ch"
   }
   ```
2. **MCP server blocks action and prompts for approval**:
   ```json
   {
     "success": false,
     "status": "pending_confirmation",
     "confirmation_required": true,
     "confirmation_details": {
       "token": "conf_tok_1730367800000_abc123",
       "summary": "Human approval required: Book Deluxe Rhine View Suite for Sacha Ramstein"
     }
   }
   ```
3. **Agent asks the human user**:
   > *"Do you confirm the reservation of the Deluxe Rhine View Suite for Sacha Ramstein?"*
4. **User approves**, and the agent re-submits with the confirmation token:
   ```json
   {
     "room_title": "Deluxe Rhine View Suite",
     "guest_name": "Sacha Ramstein",
     "guest_email": "sacha@baselhack.ch",
     "confirmed_by_human": true,
     "confirmation_token": "conf_tok_1730367800000_abc123"
   }
   ```
5. **Reservation confirmed** live on the website by Playwright!
